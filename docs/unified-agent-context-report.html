여러 로컬 AI 에이전트가 각자 따로 기억하던 결정·선호·프로젝트 상태를 하나의 MCP 호환 공유 메모리로 묶었다. 핵심 성과는 “한 에이전트에서 정한 것을 다른 에이전트 새 세션에서 다시 설명하지 않아도 되는” 로컬 전용 v1 기반을 완성한 것이다.

아키텍처

에이전트들(claude code, codex, hermes, gajaecode, lettacode) ├─ 세션 시작: inject-context.mjs │ └─ global 선호 + project:<id> 결정만 주입 ├─ 세션 중: record-fact.mjs 또는 MCP context_save ├─ 세션 종료: distill-session.mjs / claude-session-end.mjs │ └─ MCP stdio └─ mcp-memory-keeper └─ 공유 SQLite(DATA_DIR=data/memory, channel=scope 서버측 필터) 모든 저장 경로 → 중앙 secret gate → 차단 또는 redacted-only 보존

무엇을 만들었나

  • 로컬 MCP 호환 공유 메모리 서버: mcp-memory-keeper
  • 증류 사실 모델: DistilledFact
  • 스코프 규약: global / project:<git-root-basename>
  • TTL 정책: decision/preference 영구, project_state 90일
  • 원본 대화는 주입 금지, 콜드 아카이브는 redacted-only
  • 서버 장애 시 visible warning, structured log, health, metric 4증거 방출

왜 이 구조인가

  • 에이전트별 독립 기억 문제를 MCP 표준으로 통합한다.
  • 스토어는 교체 가능하게 어댑터 뒤에 숨겼다.
  • 스코프 필터를 서버 쿼리 단계에서 강제해 프로젝트 간 누출을 줄인다.
  • 비밀은 저장 전에 막거나, 아카이브에서는 원문을 버리고 redacted-only로 남긴다.

아직 v1 완료와 구분해야 할 것

v1 구현·기계 검증은 완료됐다. 다만 아래 항목은 제품 범위상 후속 확인 또는 v2 항목이다.

  • 2주 실사용 관문: 재설명 체감이 실제로 사라지는지 사용자 시간이 필요하다.
  • 외부 런타임 의존: claude CLI 로그인, codex/hermes 사용량 한도, lettacode 설치 여부는 환경 의존이다.
  • v2: 원격/셀프호스팅 MCP, claude.ai 합류, 작업 handoff는 이번 v1 범위 밖이다.

Architect 결론

구조적으로 v1은 승인 가능한 상태다. 핵심 위험이던 스코프 누출, 비밀 저장, 조용한 degraded fallback, 검증 없는 에이전트 간 전파를 각각 서버측 channel 필터, 중앙 secret gate, 4증거 degraded mode, 20경로 매트릭스로 닫았다.

다음의 올바른 운영 판단은 새 기능을 더 붙이는 것이 아니라, 2주 동안 실제 사용하면서 재설명 빈도와 라이브 하네스 의존 항목을 관찰하는 것이다.
